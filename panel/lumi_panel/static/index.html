Behaviour

Network

There is no login. With this on, anyone who can reach the Pi's address (for example on campus Wi-Fi) can control the robot. Off = this Pi only, plus whatever you expose yourself through a tunnel. Applies after the panel restarts, which also stops the robot system.

Allowed host names (optional)

Leave empty to accept any. If set, requests for other names are refused (protects against DNS rebinding). One per line, e.g. robot.example.com or *.example.com. IP addresses and localhost always work.


      

    


    
    

      

        
Remote RViz2 through the tunnel

        
Run RViz2 on any Linux machine or WSL and see the robot's map, scan, TF and plan. A Zenoh bridge carries ROS 2 traffic over one TCP connection, which Cloudflare Tunnel can forward.

        

        

          
          
        

        

      

      

        
Connection

        
        
        
The script you download is built from these two fields (hostname and domain), so changing them here and downloading again is all it takes. Domain 0 means the other machine uses the robot's own domain, so ROS tools there need no extra setup.

        

        
On the robot (one-time, Cloudflare dashboard)

        
    
          
  1. Zero Trust → Networks → Tunnels → your tunnel → Public hostname → add zenoh.example.com.
    2. 
          
  2. Service type TCP, URL 127.0.0.1:7447 (use the number form, not localhost). Put a Cloudflare Access policy on it.
    3. 
          
  3. Enable the bridge here (needs the system running).
    4. 
        

        
On the other Linux machine (headless is fine)

        
    
          
  1. Download lumi-rviz.sh and run bash lumi-rviz.sh
    2. 
          
  2. The script does the whole setup and then checks everything end to end: it installs cloudflared and the Zenoh bridge (once, nothing needs root), signs you in (a link to open in any browser), starts the tunnel and the bridge in the background, makes new terminals ready for RViz2 (a small block in ~/.bashrc), confirms the robot is reachable and that scan / tf / map data really arrives, and exits. It never starts RViz2.
    3. 
          
  3. Run it again any time (after a disconnect or restart): it only re-checks, and repairs just what is missing or unhealthy. Anything that works is left untouched.
    4. 
          
  4. Afterwards: bash lumi-rviz.sh status · topics · test (checks data really arrives) · diag (a report to paste when something is wrong) · login (the sign-in expires) · stop.
    5. 
          
  5. To open RViz2: in a new terminal just run rviz2 and add the displays you want (needs ROS 2 with rmw_cyclonedds_cpp). In the terminal you ran the script in, first run source ~/.lumi-rviz/env.sh, or use bash lumi-rviz.sh rviz from anywhere. bash lumi-rviz.sh unsetup removes the ~/.bashrc block.
    6. 
        

        
What crosses the tunnel

        
Everything, both ways: every topic, service and action on the robot, under whatever name it has now or gets later. The tunnel only carries ROS traffic; it does not filter, rename or throttle anything. Who may use it is decided by Cloudflare Access on the hostname, so anyone allowed through can do on the robot what a program running on it can (including driving it). ROS tools on the other machine see the same topic list as on the robot; only node names are not forwarded.
